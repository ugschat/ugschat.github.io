# UGS Chat

UGS Chat — шкільний інтерфейс до мовної моделі з локальними правилами, мережевим доступом лише зі школи та багаторівневими фільтрами. Це не окрема власна мовна модель і не гарантія безпомилковості: відповіді генерує OpenAI API через шкільний Cloudflare Worker.

Мета продукту — дати учням знайоме середовище для навчання, ідей і творчості, одночасно зменшуючи ризики. Інтерфейс не обіцяє абсолютної безпеки й нагадує перевіряти важливі твердження з учителем.

## Архітектура

```text
GitHub Pages (index.html, styles.css, app.js)
  └─ HTTPS JSON → Cloudflare Worker
       ├─ перевірка Origin та шкільної IP-мережі
       ├─ PII / crisis / локальні правила
       ├─ input moderation → OpenAI Responses API → output moderation
       ├─ зашифрований AES-GCM стан діалогу на клієнті
       └─ Durable Object: лише анонімні ліміти та резервування
```

Фронтенд і Worker навмисно є двома окремими Git-репозиторіями. Каталог `worker/` ігнорується репозиторієм GitHub Pages та розгортається окремо.

## Поведінка чатів

- У межах однієї вкладки можна створювати й перемикати кілька чатів.
- Новий чат не видаляє попередній, навіть якщо відповідь ще генерується.
- Чати зберігаються лише в оперативній пам’яті вкладки та зникають після закриття або перезавантаження.
- Поточну розмову можна скопіювати або локально зберегти через системне вікно друку як PDF. На сервер для цього нічого не надсилається.
- Технічний стан кожного чату зашифрований AES-GCM, має TTL 12 годин і прив’язаний до випадкового `sessionId`.
- На мобільному пристрої `localStorage` містить лише випадковий ідентифікатор для добового ліміту, а не текст чатів.

## Захисні шари

- доступ лише з дозволених Origin та IP/CIDR;
- локальне виявлення персональних даних і кризових фраз до виклику моделі;
- модерація входу та виходу;
- системні правила для віково доречного навчального стилю;
- обмеження кількості запитів, сесій та генерацій;
- окремий валідатор HTML-артефактів;
- sandboxed iframe без мережі, сховищ, форм, навігації, камери, мікрофона й геолокації;
- CSP, `nosniff`, `no-referrer`, заборона вбудовування API у frame.

Жоден із цих шарів не є безпомилковим. Операційні вимоги й відомі межі описані у [SAFETY.md](SAFETY.md).

## Локальна перевірка

Фронтенд не потребує збірки:

```powershell
node --check app.js
```

Worker:

```powershell
cd worker
npm test
npm run check
```

`npm run check` запускає тести й `wrangler deploy --dry-run`, тому `wrangler` може бути завантажений через `npx`.

## Розгортання

1. Окремо опублікувати статичний репозиторій через GitHub Pages.
2. У Worker задати `OPENAI_API_KEY`, `CHAT_STATE_SECRET` (щонайменше 32 випадкові байти) та `ALLOWED_IPS` як секрети/змінні Cloudflare.
3. За потреби доповнити `SUPPORT_CONTACT_TEXT` конкретним кабінетом, внутрішнім номером або іншим шкільним шляхом ескалації. Базові контакти вже вказані в UI: технічні питання — пан Артем, учитель інформатики; психологічна підтримка — шкільний психолог.
4. Запустити `npm test`, `npm run check`, потім `npm run deploy` у каталозі `worker/`.
5. Перевірити `/health` та основні сценарії саме зі шкільної мережі.

Для сервісу, доступного дітям до 13 років, запуск не слід вважати завершеним без схваленого OpenAI Zero Data Retention і перевірки вимог дитячої приватності відповідальною особою школи. `store: false` уже ввімкнено, але саме по собі не дорівнює Zero Data Retention.

## Перспективні зміни

Ці ідеї свідомо не входять до поточного релізу й потребують окремого продуктового рішення:

- ненав’язливі навчальні дії під відповіддю;
- повідомлення про невдалу відповідь без автоматичного прикріплення чату.
